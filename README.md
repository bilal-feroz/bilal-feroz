## How I approach systems

**Start with the real workflow.** I map the people, decisions, data, hand-offs, and failure points before choosing the interface or architecture. A strong prototype should explain the operation as clearly as it demonstrates the technology.

**Design feedback into the interface.** Operators need visible machine state, useful alerts, deliberate controls, and a clear recovery path. I treat those feedback loops as core system behaviour, not a layer added after the integration works.

**Treat hardware as a system constraint.** Sensors, edge devices, networks, timing, and commissioning conditions shape the software. I test assumptions where code meets equipment and use those results to improve the product flow.

**Keep AI accountable.** Agent and document workflows should expose evidence, retain human review where it matters, and fail clearly when required context or services are unavailable.

**Build toward use, not only the demo.** I move quickly through prototypes while keeping maintainability, deployment, UX consistency, and the next validation step visible.
